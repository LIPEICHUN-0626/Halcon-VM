# S132 模板位姿驱动图像对齐

状态：2026-10-02 部分实现（待集中验证）。以下代码路径已接入，不代表编译、操作体验或现场精度验证通过。S130 良品学习仍要求在真正对齐图中建立良品样本，并保证共同有效域覆盖检测 ROI。

## 已写入代码路径

- A：原图像处理分类的“定位图像对齐”，统一参数小窗只把输出范围作为常用字段；固定参考状态/显式取当前位姿、按需插值和原图/对齐图对照，不增加常驻工具栏按钮或压窄流程。
- B：显式 Image/Pose，同图像链与真实有限像素守卫；当前位姿到固定参考的 HALCON 刚体重采样，半像素矩阵适配，真实输入域→支持域→同矩阵变换→输出画布交集，发布独立 Image/Region/AlignedPose、变换矩阵/平移旋转与稳定参考坐标。
- 参考只进原草稿，F5/应用复用；NCC 输入位姿的 ModelVersion 必须等于已应用模型，不消费新模板未应用试运行结果。参考来源签名涵盖图像及定位配置，不随当前帧变化，改变配置须显式重取。
- 支持 1/3 通道 byte/int2/uint2/real 与 16M 像素上限；real 非有限值拒绝。双线性保守侵蚀 3×3 支持域，身份变换亦少一像素边界；最近邻不侵蚀。无位姿/跨链/空域不回退旧结果。
- 原图 ROI 不自动迁移；输出覆盖域与对齐图属于同一新链。学习示例 Source→NCC→对齐→GrayStat，GrayStat 同时订阅 Image/Region，避免黑边统计；不自动训练、采参考或运行。
- 参考配置保存/撤销/深复制复用既有路径；显式粘贴/整流程复制先核对原身份，再迁移依赖签名和上下文，保留参考数值/版本，随后续接下游良品模型复制。无法证明来源合法则保留旧身份并明确失败。
- 旧 Shape 的 HALCON 变换位姿只在本消费者转换到真实像素，不改变稳定 Shape 算法和标量输出。

实现：`MainWindow.S132.cs`、`MainWindow.S132.Clone.cs`、`MainWindow.S132.Learning.cs`、`Models/VmPoseImageAlignmentS132.cs`，及原 XAML/执行器/参数/元数据/坐标解析/帮助/方案复制接口。未逐轮编译、测试、启动或验收；Git 已验证批次仍 6/10。下一 S133 见 `S133_OCR_CHARACTER_RESULTS_AND_VALIDATION.md`。

## 设计基线与集中检查范围

A 线：在原图像处理分类和统一参数小窗中提供紧凑的图像/位姿来源、显式参考姿态获取、输出范围与输入/对齐图对照。默认首屏最多四项任务字段，插值与边界等低频设置按需展开；不增加永久顶部按钮、不压窄纵向流程。参考姿态必须由用户明确保存到草稿，不能随着查看另一个匹配候选或运行结果自动漂移。

B 线：把 NCC/Shape 等正式 Pose2D 的当前位置变换到已保存参考姿态，使用实际 HALCON 刚体变换和图像重采样输出受管 Image，而不是只移动 ROI、画一条示意线或重命名输入图像。已有仿射图像工具接受手填变换且只订阅 Image，本主题补正式 Pose2D 订阅和参考姿态工作流；复用稳定变换实现，不无故重写算子。实施前核对本机 API 与官方图像坐标/插值语义；显式输入 Image 和 Pose2D，只有同一图像坐标来源可执行，无匹配、无位姿、跨链/世界坐标、无效参考或空输出域必须明确失败，不回退旧对齐图。

输出须有独立且可复现的图像坐标身份、真实有效域、可供下游继续处理的 Image 和本次变换/位姿摘要。原图 ROI 不得默认冒充已经在对齐图中：明确区分源图几何与参考坐标检测 ROI，跨链继承继续拒绝；需要迁移时必须按同一真实变换显式生成新几何并保留来源。不要把 S62 位置修正或 S128 径向映射宣称为本主题的刚体图像归一化。

完整操作路径：图像源→模板定位→保存明确参考→图像对齐→在对齐图配置检测 ROI→良品学习/检测→数值判定与图像对照→保存、复制、撤销、打包及中文帮助/显式示例。NCC 查看候选不改变正式最佳 Pose；如需要另一个候选用于算法，必须通过明确数据选择契约，不能暗中改变输出。图像变换句柄、有效域和快照释放复用原生命周期；草稿/F5/应用及来源变化守卫沿用同一状态。

首版以 2D 刚体平移/旋转归一化为完整主题，不冒称缩放、透视、非刚性、光照归一化或现场精度认证。优先打通定位→真实 Image→良品检测的工业任务，不以后台变换对象或仅叠加 UI 凑任务数。后续 S133 和 S134–S143 工程/生产主题仍按 `S150_PRODUCT_TARGET.md` 推进。
