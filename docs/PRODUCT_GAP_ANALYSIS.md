# 产品差距分析

更新日期：2026-08-24
目标：海康 VM / VisionMaster 类型工业视觉平台体验 + HALCON 算法内核

代码核验基线：S65 已验证源码（Legacy 与 S09-S65 共 58/58；双尺度实体 WPF UI、HALCON Shape/Pose2D/位置修正及圆周卡尺 `Point2D[] -> 点集几何` 真链、XAML 入口 0 缺失、Debug/Release 0 警告 0 错误和双版本 8 秒启动响应通过；本 Git 批次达到 10/10）
官方参照：`docs/VM_OFFICIAL_REFERENCE_SPEC.md`

## 0. 官方资料复核后的总判断

当前软件已经完成官方 VM 开发主分区、首批右侧常驻模块配置、八类真实 ROI/逐区结果、连续 Image/Region/XLD 跨工具订阅、图像上下文、单方案可靠生命周期、首版二维真实连接画布、独立生产运行页、受控运行界面配置、本地批次追溯，以及可连续浏览、双样本比较、逐层控制、逐工具明细和跨图片 Number 趋势的只读结果回看；HALCON 链也已延伸到圆度/凸性筛选。但**仍不接近完整海康 VM**。

2026-08-21 用户进一步指出左侧工具过少，复杂项目无法直观看到可用能力。代码核验确认当时不是只有 8 个工具，而是实际注册 59 个工具；S62 已恢复 59 工具/9 类完整目录，S65 增至 60 个，并增加由真实元数据生成、默认收起的能力/端口预览。紧凑单行、分类折叠、搜索、常用、收藏和最近继续保留，因此“降低按钮噪声”不再错误等同于“隐藏能力”。S63-S65 进一步验证“完整目录 + 当前任务 + 按需契约”可以同时成立，没有新增顶部按钮。整个 `MainWindow` 单体结构、缺失工具类别、长流程插入导航和设备资源仍明显落后于完整 VM，因此当前结论仍是“方向纠正且复杂项目能力开始可发现”，不是“已接近完整 VM”。

用户新增的脚本需求与官方 VM 的 SDK、全局脚本和自定义模块方向一致。S58 已交付可传参的受信任内联 C#/外部 DLL 正式流程工具，S59 交付四种类型的全局变量及确定性读写，S60 交付稳定 ResourceId、版本化受管副本、刷新/替换和引用保护，S61 又交付每实例稳定 ID 的 Number/String/Boolean/ResultCode 命名输入、参数、输出 Schema 与真实动态标量端口，不再只有 HDevelop 兼容执行、内部结构、易漂移裸路径或固定业务字段；但变量和资源仍是当前单方案本地状态。S65 只补了首个正式 `Point2D[]` 视觉链，并不等于脚本已支持数组；脚本之后仍缺数组/Geometry/HObject、依赖打包、帮助资产、正式 SDK 和更强隔离；全局层仍缺触发、队列与多流程。

本结论来自海康[VM 产品页](https://www.hikrobotics.com/cn/machinevision/visionmaster/)、[VM5.0 发布资料](https://www.hikrobotics.com/cn/publish/)和[官方 VM3D 用户手册](https://pinfo.hikrobotics.com/hkws/unzip/20240919112534_17943_doc/index.html)。VM3D 的通用框架用于确认 VM 家族页面结构，不用来冒充本项目已有 3D 能力。

## 1. 当前活动架构

- `App.xaml` 启动 `MainWindow.xaml`，因此 WPF 主窗口是唯一活动产品入口。
- `MainWindow` 直接持有图像、ROI、模板、通讯、配方、结果和运行状态，并以事件处理器驱动。
- `RecipeService` 已独立承担版本化 JSON、原子替换、单份备份、布局/最近记录和恢复副本；`MainWindow` 仍负责脏状态与用户提示，尚未形成完整工程域服务。
- `MainForm` 和 `TemplateCreateForm` 仍参与编译，但没有活动启动引用；其中相机、旧模板 Mask、显示框编辑和结果筛选等旧能力对 WPF 用户不可达。S36 的活动 WPF 工具级 ROI 屏蔽区是独立产品实现，不能反向证明这些旧入口已迁移。
- 已有统一工具实例、类型化 IN/OUT 端口、Number/Image/Region/XLD/Pose2D/Point2D/Point2D[] 订阅、八类 ROI 图层及面 ROI 屏蔽角色、统一 ROI/屏蔽/Region/XLD 图层属性、XLD 单对象检查、连续图像/区域/XLD 工具链、首条圆周卡尺 Point2D[]→点集几何链，以及主要 Image/Region/XLD 处理与测量；输出使用托管 HImage/HRegion/HObject(XLD) 并在重跑/删除/关闭/历史恢复/配方重载时释放。仍没有完整 XLD 目录、通用数组、Line/Circle/Geometry/HObject 端口和通用测量几何对象。
- 活动流程默认二维连接画布，依赖分层、类型曲线、方向、标签、等待/异常和选中高亮来自真实绑定；连接 Inspector、端口导航和 OUT→IN 拖拽作用于真实订阅。画布支持多选/批量、网格布局和组织型 Group；50 项纯 DTO 撤销/重做在 S32 已包含 ROI 图层、图像拖动和数值几何应用，并有断点/单步、常驻调试监视和运行到所选。顺序列表继续承担精确确定性排序，但仍无真实多流程/并行/执行型 Group、全量动作历史面板、表达式监视或运行到光标。
- 右侧常驻模块配置工作台覆盖本地图像源、图像通道、滤波、增强、尺寸缩放、图像镜像、图像旋转、图像仿射变换、极坐标展开、ROI 图像提取、双图像差分、阈值、Region/XLD 处理/仿射与拟合、四类测量、Blob、Gray、Edge、Shape、NumericJudge 的基本/运行/输入/ROI/结果/帮助、草稿、应用/撤销和试运行；Shape 另有每实例模型资源、训练 ROI、搜索 ROI、候选表/图形和托管 XLD，ROI 页另有八类数值几何与检测/屏蔽角色属性，图像区另有双十字常驻配置。HDevelop 仍为兼容入口。

## 3. 只有内部结构或不可达的实现

1. `HalconImageService` 的相机采集方法只由不可达 `MainForm` 使用，当前 WPF 用户无法配置和采集。
2. `MainForm` 内较丰富的模板 Mask、显示框控制点、相机和结果过滤没有迁移到活动 WPF；S36 仅另行交付工具级 ROI 屏蔽区，不等于旧模板 Mask 已迁移。
3. `RoiService` 没有活动引用。
4. `InspectionResultStore.Query` 只在不可达旧窗口中使用；WPF 结果区不能查询筛选。
5. WPF 的旧配方 `TemplatePath/TemplateOptions` 已在 S63 迁移到首个 Shape 实例并可由模型元数据恢复参数；`LastImageDirectory` 的完整方案恢复语义仍需继续核验，不能笼统宣称全部旧工作区状态已迁移。
6. WPF 原图副本和首条模块 Image 输入/输出已进入上下文切换，但多数视觉工具尚无独立处理中间图/结果图 Image 输出。
7. `RoiService`、旧 WinForms 的模板 Mask/显示框控制点和部分相机入口没有迁移到活动 WPF，不能计入当前产品能力；活动 WPF 的 S36 工具级屏蔽区按其自身代码与测试计入。
8. 工具流、实例参数、端口、ROI/屏蔽区、真实连接画布、多选/批量操作、端口拖线、手动布局、首批撤销/重做、组织型 Group、流程断点/单步/监视/运行到所选、结果图层和模块剪贴板已有活动 UI；当前注册 60 个工具并有按需元数据契约预览，覆盖双 Image/双 Region/双 XLD 汇聚、Image 变换、Shape/Pose2D 定位、首条 Point2D[] 点集链、XLD 生产/处理/拟合/关系及多类测量。但采集、识别、标定、跨坐标、输出、设备和更多高级检测类别仍薄弱，通用数组与 Line/Circle/Geometry/HObject 仍缺，距离 VM 的完整模块契约很远。

## 4. 用户重点问题逐项回答

### UI 是否真的接近海康 VM

主分区和真实调试路径已经存在，S49-S61 已把顶部、图像、流程节点、右侧任务、调试器、底部信息、工具字段、全局变量、外部资源和脚本接口逐步改成渐进展开；S62 修正过度隐藏工具的问题，S63 把高价值 Shape 模型任务迁入当前对象，S64 又补按需端口数据与 Pose2D 跟踪。完整 59 工具/9 类默认可见且没有恢复顶部按钮墙。当前更大的 UI 差距转为标定/跨坐标/设备/输出等工具类别不足、HDevelop 受管化、触发/队列/方案任务页、窗口单体解耦、多画面、表达式监视、全量动作历史、真实并行、执行型 Group/多流程、ROI 继承、权限和完整运行界面设计；仍不能笼统写成“已接近完整 VM”。

### 主要参数是否仍依赖弹窗

## 5. 已识别的具体风险

- HALCON 合成双尺度 L 型 Shape 已完成训练/保存/加载/多目标搜索，但仍无用户真实外部产线图像与模板，现场分数、尺度、遮挡和节拍未验证。
- 训练后未另存 `.shm` 的模板没有持久路径，保存配方时无法完整恢复。
- 配方目前只有单份 `.bak` 和一个活动恢复副本，没有版本历史、签名、权限、自动换型事务或跨机资源打包；`.jw/.handle` 仍无证据。
- S53 流程 TCP 已有连接/发送/接收超时、编码、行尾与 1 MiB 响应保护，S54-S55 已增加通用文本组装和解析；但仍是每次执行独立连接，没有持久资源、心跳、自动重连、工业协议帧编排、字段映射或真实设备验证。旧通讯页的直接读取限制仍存在。
- 连续运行仍由 UI `DispatcherTimer` 触发，HALCON 工具在 UI 线程同步执行；已支持步骤间断点、单步、继续、暂停/停止/超时和防重入，但不能中断单个长耗时算子，尚未形成生产线程、硬取消和完整节拍治理模型。
- 结果图像快照全部驻留内存，长时间运行存在内存增长风险。
- 当前没有真实 `.jw/.handle`、PLC 地址表、BSB 标定和协议样本，相关兼容性仍缺权威验证材料。
