# 产品差距分析

更新日期：2026-08-08
目标：海康 VM / VisionMaster 类型工业视觉平台体验 + HALCON 算法内核

代码核验基线：S35 已验证源码（2026-08-08 收口，新 Git 批次 10/10，本轮统一提交/推送）
官方参照：`docs/VM_OFFICIAL_REFERENCE_SPEC.md`

## 0. 官方资料复核后的总判断

当前软件已经完成官方 VM 开发主分区、首批右侧常驻模块配置、八类真实 ROI/逐区结果、连续 Image/Region/XLD 跨工具订阅、图像上下文、单方案可靠生命周期和首版二维真实连接画布，但**仍不接近完整海康 VM**。S35 补上线/点 ROI 的真实工具栏、控制点、常驻数值属性、配方和编辑历史，并以 HALCON `rotate_image` 建立 `Image -> rotated Image -> Region` 闭环；0°/90°/180°/270°与任意角、非方图宽高/定位像素、五插值、灰度/RGB、domain、异常和快照释放均由运行结果确认，不是只有内部结构或按钮。当前执行仍为确定性线性调度，单个 HALCON 算子不可中断；Group 不是执行单元，也没有表达式监视、运行到光标、真实并行或多流程；图像区仍缺多画面和缩略图，十字线尚无标签/快捷键/撤销，圆环壁厚工具仍靠数值输入，成组结果仍为字符串而非类型化数组；Shape 兼容叠加尚未进入逐层清单，历史尚未覆盖模板/全部方案动作；屏蔽区、位置修正、ROI 继承、Shape/HDevelop 完整常驻配置、完整图层属性、通用几何姿态、资源/权限/运行界面、完整工具目录和生产运维也未完成，因此只能称为 VM 化 HALCON 工作台的早期产品闭环。

本结论来自海康[VM 产品页](https://www.hikrobotics.com/cn/machinevision/visionmaster/)、[VM5.0 发布资料](https://www.hikrobotics.com/cn/publish/)和[官方 VM3D 用户手册](https://pinfo.hikrobotics.com/hkws/unzip/20240919112534_17943_doc/index.html)。VM3D 的通用框架用于确认 VM 家族页面结构，不用来冒充本项目已有 3D 能力。

## 1. 当前活动架构

- `App.xaml` 启动 `MainWindow.xaml`，因此 WPF 主窗口是唯一活动产品入口。
- `MainWindow` 直接持有图像、ROI、模板、通讯、配方、结果和运行状态，并以事件处理器驱动。
- `RecipeService` 已独立承担版本化 JSON、原子替换、单份备份、布局/最近记录和恢复副本；`MainWindow` 仍负责脏状态与用户提示，尚未形成完整工程域服务。
- `MainForm` 和 `TemplateCreateForm` 仍参与编译，但没有活动启动引用；其中相机、Mask、显示框编辑和结果筛选等能力对 WPF 用户不可达。
- 已有统一工具实例、类型化 IN/OUT 端口、Number/Image/Region/XLD 订阅、八类 ROI 图层、连续图像/区域/XLD 工具链、极坐标展开、ROI 图像提取、图像尺寸缩放、图像镜像、图像旋转、双 Image 差分/动态阈值、双 Region 集合运算、Region→XLD 测量、XLD→XLD 筛选/分段及多类拟合/关系、单/线性/圆周卡尺和圆环壁厚/同心度测量；输出使用托管 HImage/HRegion/HObject(XLD) 并在重跑/删除/关闭/历史恢复/配方重载时释放。仍没有类型化数组、几何/姿态数据、通用测量几何对象和完整图像处理目录。
- 活动流程默认二维连接画布，依赖分层、类型曲线、方向、标签、等待/异常和选中高亮来自真实绑定；连接 Inspector、端口导航和 OUT→IN 拖拽作用于真实订阅。画布支持多选/批量、网格布局和组织型 Group；50 项纯 DTO 撤销/重做在 S32 已包含 ROI 图层、图像拖动和数值几何应用，并有断点/单步、常驻调试监视和运行到所选。顺序列表继续承担精确确定性排序，但仍无真实多流程/并行/执行型 Group、全量动作历史面板、表达式监视或运行到光标。
- 右侧常驻模块配置工作台覆盖本地图像源、图像通道、滤波、增强、尺寸缩放、图像镜像、图像旋转、极坐标展开、ROI 图像提取、双图像差分、阈值、Region/XLD 处理与拟合、四类测量、Blob、Gray、Edge、NumericJudge 的基本/运行/输入/ROI/结果/帮助、草稿、应用/撤销和试运行；ROI 页另有八类数值几何属性，图像区另有双十字常驻配置。Shape/HDevelop 和模型训练仍为兼容弹窗。

## 3. 只有内部结构或不可达的实现

1. `HalconImageService` 的相机采集方法只由不可达 `MainForm` 使用，当前 WPF 用户无法配置和采集。
2. `MainForm` 内较丰富的模板 Mask、显示框控制点、相机和结果过滤没有迁移到活动 WPF。
3. `RoiService` 没有活动引用。
4. `InspectionResultStore.Query` 只在不可达旧窗口中使用；WPF 结果区不能查询筛选。
5. WPF 保存 `LastImageDirectory` 和 `TemplateOptions`，但加载路径没有完整消费这些信息。
6. WPF 原图副本和首条模块 Image 输入/输出已进入上下文切换，但多数视觉工具尚无独立处理中间图/结果图 Image 输出。
7. `RoiService`、旧 WinForms 的 Mask/显示框控制点和部分相机入口没有迁移到活动 WPF，不能计入当前产品能力。
8. 工具流、实例参数、端口、ROI、真实连接画布、多选/批量操作、端口拖线、手动布局、首批撤销/重做、组织型 Group、流程断点/单步/监视/运行到所选、结果图层和模块剪贴板已有活动 UI，但只有三十类工具、双 Image/双 Region/双 XLD 汇聚、首批 Image 变换、XLD 生产/处理/拟合/关系工具和单/线性/圆周/圆环测量工具；类型化数组、通用几何数据和完整视觉工具目录仍缺，距离 VM 的完整模块契约很远。

## 4. 用户重点问题逐项回答

### UI 是否真的接近海康 VM

主分区和首批调试路径已经明显接近，S16-S35 又让真实连接、布局、编辑历史、组织型 Group、断点/监视、结果图层、三类测量域、八类 ROI 图像/数值双向编辑、单/双画面输入输出对比和双十字进入默认工作区。仍不能称为完整复刻：双画面只是首版，仍缺多画面/缩略图；执行仍是线性调度，缺表达式监视、运行到光标、全量动作历史、真实并行、执行型 Group/多流程；屏蔽区/位置修正、Shape/HDevelop、完整图层属性、圆环壁厚/通用测量几何编辑、方案树/模板、资源、权限、运行界面和大量工具目录也尚未实现。

### 主要参数是否仍依赖弹窗

**首批主要视觉参数已不再依赖弹窗，但迁移尚未完成。** S10-S35 已把三十三类工具中的主要图像/Region/XLD/测量/判定参数迁入右侧常驻配置；八类 ROI 已有控制点和统一数值几何属性，单卡尺、线性阵列和圆周找圆测量域可在图像区直接编辑。屏蔽区/位置修正、圆环壁厚及其他通用测量几何仍缺或只靠数值参数；HDevelop、Shape 模板训练和模型管理仍使用兼容弹窗，通用 Schema 与连续试运行也未完成。

### 流程工具区是否符合 VM 习惯

S04/S12 已补齐线性调试、区段运行和拖拽插入，S15 增加真实端口/消费者，S16 增加真实二维连接、依赖分层、分支/汇聚、缩放/平移/适应和顺序视图切换，S17/S18 增加连接/端口检查与导航，S19 增加多入口复制/粘贴/副本，S20 增加橡皮框与真实批量动作，S21 增加 OUT→IN 创建/替换/重连和即时拒绝反馈，S22 增加模块拖动、网格吸附、对齐/等距及配方坐标回读，S23 增加主要工具流动作真实撤销/重做，S24 增加组织型 Group，S25 增加断点/单步/继续，S26 增加常驻调试监视和运行到所选。S27 主要改进图像工作区而非流程调度。流程习惯明显改善，但仍缺表达式监视、运行到光标、全量动作历史、真实分支调度、执行型 Group 和多流程。

### 图像区和 ROI 是否完善

S03-S35 的 ROI/Region/XLD 图层、图像上下文、连续数据链、八类控制点、三类测量域、常驻数值几何、裁剪/缩放/镜像/旋转坐标隔离和单/双画面输入输出对比均是真实闭环。Shape 兼容叠加尚未纳入逐层清单，圆环壁厚和其他通用测量域尚不能在图像内直接编辑，还缺屏蔽区、位置修正、ROI 继承、多画面/缩略图、完整图层属性/选择联动、完整图像处理目录和多数工具的中间图/结果图输出。

### 通信、计算、坐标和 BSB 是否有真实入口

- 通信：有真实 TCP Client/Server 页、手动收发和自动结果入口，但缺工业通信管理。
- 计算：有真实数值判定工具和 Number 订阅，但没有通用数学、逻辑、数组、字符串、表达式和脚本工具集。
- 坐标/标定：没有活动流程工具或配置入口。
- BSB：没有活动工具，且当前按用户指令暂停。

### 是否有大量只有内部结构、没有用户价值的实现

存在，最明显是相机采集服务、旧 `MainForm` 的相机/Mask/结果筛选、`RoiService` 和 `InspectionResultStore.Query`。它们对活动 WPF 用户不可达，因此只能作为潜在迁移资产，不能计入已交付产品能力。

## 5. 已识别的具体风险

- 无真实 Shape Model 模板样本，模板训练/保存/加载的本轮回归证据不足。
- 训练后未另存 `.shm` 的模板没有持久路径，保存配方时无法完整恢复。
- 配方目前只有单份 `.bak` 和一个活动恢复副本，没有版本历史、签名、权限、自动换型事务或跨机资源打包；`.jw/.handle` 仍无证据。
- TCP 以每次 `Read` 直接解码消息，没有工业协议分帧；没有连接超时、心跳和自动重连。
- 连续运行仍由 UI `DispatcherTimer` 触发，HALCON 工具在 UI 线程同步执行；已支持步骤间断点、单步、继续、暂停/停止/超时和防重入，但不能中断单个长耗时算子，尚未形成生产线程、硬取消和完整节拍治理模型。
- 结果图像快照全部驻留内存，长时间运行存在内存增长风险。
- 当前没有真实 `.jw/.handle`、PLC 地址表、BSB 标定和协议样本，相关兼容性仍缺权威验证材料。
