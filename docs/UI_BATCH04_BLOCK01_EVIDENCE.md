## A：采样、学习和模型状态清楚

- 保留原S130工具、原三项常用参数及统一参数小窗；展开学习任务只面对加入当前良品、学习、样本数和短进度。列表/缩略预览、外部导入、移除和清空进入“查看 / 管理样本”，不建立第二训练平台。
- 缺明确Image输入、没有当前有效上游快照或来源草稿未应用时，采样/学习禁用并提供悬停原因。导入另需显式确认外部图片已对齐且均为良品。就绪提示只是配置前提，不进行隐藏SDK检测；真正取样/学习仍核验来源、类型和尺寸。
- 模型短状态区分新模型待应用、已应用模型及参数草稿。F5临时借用草稿执行后，再从恢复的正式参数刷新状态，修复画面误报“已应用”。完整版本/尺寸/资源解释悬停，状态不冒资源验证或现场合格。
- 取消学习只请求停止，结束后显示已取消并保留旧版本；不把被包装的取消异常留成“正在取消”。外部文件选择前后及训练迟到结果补session/Flow/实际实例/草稿代际/编辑租约检查，不把其他模块消息写入当前任务。

## B：真实发现并修复的阻断

1. 原训练成功后调用`clear_train_data_variation_model`再保存，而检测每次仍调用`prepare_variation_model`，第一次真实F5即报HALCON8545。已取消保存前清理，保留重新准备当前容差所需统计；每次检测仍独立读/准备/释放句柄，不共享可变模型。
2. 新图像源的默认File模式可以为null；原来源签名按原始null取哈希，保存规范化为File后，重开同一工程被误报不同来源。现在签名使用有效模式规范化，来源ID、设备标识和上游参数保护不放宽。旧签名/旧模型不静默重写，无法核实者需用户明确重建。
3. 对旧已清理统计的模型，明确提示重新学习并应用；不自动学习、不跳过准备、不沿用旧阈值冒充当前设置。旧文件保持原样。

官方核对：HALCON20.11说明清理训练数据后的模型只用于比较，不能继续读取原理想图/波动图；prepare由训练图计算当前阈值图。参见 [clear_train_data_variation_model](https://www.mvtec.com/doc/halcon/2011/en/clear_train_data_variation_model.html)、[prepare_variation_model](https://www.mvtec.com/doc/halcon/2011/en/prepare_variation_model.html)。本机真实8545与修复后结果是本项目证据，不以文档替代运行。
