# S122 Modbus 寄存器类型与字序解码

状态：A/B 开发路径已写入，部分实现（待集中验证）；本轮未编译、回归、鼠标验收或连接 PLC/串口设备。S121 同样待集中验证。

已写入的 A 线：Modbus TCP/RTU 原参数窗在 03/04 读寄存器时就地显示主值类型；只有多寄存器类型才显示字序，不新增顶部按钮。离线帧解析显示“原始寄存器字 → 类型/字序 → 主值”或明确错误；结果首屏显示主值、精确文本、解释与原始数量，完整帧/原始数组仍在“更多”。

已写入的 B 线：同一解码器覆盖 U16/I16、U32/I32/F32、U64/I64/F64，取响应中前 1/2/4 个连续寄存器，支持高字在前/低字在前；每个 16 位寄存器内部保留协议高字节在前。03/04 的真实和模拟响应共用该路径，`Value` 仅发布有限且可准确表达的 Number，`DecodedText` 保留精确文本，`Values` 保留全组原始寄存器。数量不足、非整数原始字和 NaN/Infinity 给错误且不发布主值；64 位整数超过 2^53 时保留精确文本、不发布伪精确 Number，并给明确状态。01/02 位及 05/06 写入回显保持原语义、无新写入功能。

依据：[Modbus Application Protocol V1.1b3](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf) 定义 16 位寄存器与寄存器内高字节优先；多寄存器字序是本产品显式配置，不称作协议统一规定。[Microsoft BitConverter 文档](https://learn.microsoft.com/en-us/dotnet/api/system.bitconverter.todouble?view=net-10.0)说明浮点位转换依赖体系字节序，因此实现由 16 位字明确组装位型后转换。尚不支持字节内交换、工程缩放/单位、任意起始偏移、所有厂商排列或设备现场验证。

A 线：Modbus TCP/RTU 仍以原紧凑参数窗配置 03/04 读任务；在结果页默认展示用户选择的主值及单位/字序摘要，原始寄存器和详细解码按需展开。为常见 16/32/64 位有符号/无符号整数与 IEEE 浮点提供少量明确、可学习的类型和寄存器字序选项，不把所有排列和工程参数同时铺开。离线帧调试页能直观看到“原始字 → 主值”的转换与错误。

B 线：基于原始 16 位寄存器读取结果做类型化解码，按功能码、数量和类型严格校验，不猜测设备字序、缩放或地址基准；Number 主输出与 Number[] 原始值共存，继续供数值判定/计算使用。64 位整数超过双精度精确整数范围时保留精确文本并拒绝伪精确 Number。写入仍仅 05/06 单点且不自动重放；模拟和真实路径使用同一解码契约，失败不保留旧值。集中验证前不宣称设备兼容或生产可用。
