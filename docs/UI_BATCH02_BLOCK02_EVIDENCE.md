# 界面第二批 · 02 模板草稿、匹配与正式版本

2026-10-14。复用原S89 Shape制作、S63资源、S131 NCC、S145目标资格和唯一参数小窗，不重建训练平台。第二批2/10，暂不Git；首批`61adc04`已上传。

## 实读发现与实际修改

- Shape原读取输入/训练会先ApplyDockConfigurationDraft，训练立即替换tool.Parameters和正式SDK资源，与NCC仅进草稿不同；训练ROI还默认选择列表第一项。现在读取不自动应用，输入订阅草稿不一致时拒绝读取；明确框选或明确选定当前图像ROI后训练，受管独立版本只进入原Shape参数草稿字段，不修改正式路径/参数、添加全局训练ROI或直接提交历史。
- Shape制作和导入.shm统一F5/应用语义；原读取保留编辑授权重核，模板制作保留原lease/忙碌/输入预览身份校验。取消修改恢复已应用路径。训练失败或旧预览不覆盖旧文件；旧SDK文件版本保持。
- Shape F5临时加载的新模型在恢复已应用参数时若不匹配正式路径，就从原缓存释放，避免空正式路径却因草稿缓存表现为已具备模型。正式目标资格仍由原S145定义键/输入/实际模型代际核实，不能从草稿取得正式资格。
- 导出模型改为SDK SaveCopy，写独立模型与原元数据/掩膜，不改当前TemplatePath或定义路径。窗口导出拒绝同一路径；导入只写入草稿，不偷偷改变正式工具。保留旧Save供其他已授权正式版本路径使用。
- 原制作预览由175/190缩到150px，制作后两类都收起，露出两项匹配常用字段；新/已应用模型状态清楚，路径/SHA移悬停。Shape名称、明确训练ROI和文件管理进入原更多；读取、框选、制作草稿仍原入口，不增加永久顶栏或第二参数窗。
- 普通同步参数F5复用原运行Action/执行器，但把错误交给原参数试运行边界内联显示，不经过额外MessageBox。其他独立操作仍沿原提示，不宣称所有弹窗去除。

## NCC实际旋转范围缺陷与来源

隔离默认-180°/360°模型制作后，GetNccModelParams实际起点为-181.353383458647°，范围360°，步长2.70119909887951°；旧线性端点判断把同一个整周视为超界。只读直接SDK探针用原-180°/360°找到1个目标、Score=1，确认不是模型或许可失败。

[HALCON 20.11 create_ncc_model官方说明](https://www.mvtec.com/doc/halcon/2011/en/create_ncc_model.html)解释角度采样可能调整起点以包含零；[find_ncc_model官方说明](https://www.mvtec.com/doc/halcon/2011/en/find_ncc_model.html)说明搜索受创建范围约束。本修复在实际模型确实覆盖整周且请求整周时，以实际模型起点表达同一360°范围；有限范围只允许可完整覆盖的等价周期表达，仍拒绝真正越界，不靠截断、改成零角或降低测试目标通过。部分窄范围跨整周表示缝仍未证明完整分段搜索能力，不冒全角度支持验证。
